# -NO.1
코스 난이도별 탐색, 크루 채팅·빠른 상태 공유, 개인 산행 GPS 기록, 안전 안내를 제공하는 등산 중심 인터랙티브 프로토타입 (산책로·둘레길 부가 지원)

## 핵심 서비스 개요

- **메인 영역**: 등산 (산행 코스, 입산/하산, 크루 산행, 트레일 마라톤/대회)
- **부가 영역**: 산책로·둘레길 (초보자·가벼운 일상 코스 서브 지원)

## 핵심 기능

1. **코스 탐색**: 정적 시연 데이터에서 난이도별 코스를 필터링하며, AI·날씨 기반 추천은 연결되어 있지 않습니다.
2. **등산자 커뮤니케이션 채널**: 코스 채팅과 빠른 상태 공유를 제공합니다. 동행·택시 요청은 메시지 예시이며 자동 매칭은 구현되어 있지 않습니다.
3. **등산 장비 대여 및 판매**: 화면 예시만 있으며 실제 상품·예약·결제는 제공하지 않습니다.
4. **크루 소통 및 개인 GPS 기록**: 코스별 회원 채팅방과 빠른 상태 메시지를 제공합니다. GPS 기록은 별도 동의 후 본인 기록으로만 저장하며 크루 위치 공유는 지원하지 않습니다.
5. **산행 안전 안내**: 가상 안전 도식과 추정 고도 단면은 시연용입니다. 실제 휴게시설·사고 데이터, 실시간 위치 공유, 자동 신고는 제공하지 않습니다. 비상 안내에서 `tel:119` 링크를 제공하지만 전화는 사용자가 직접 실행해야 합니다.
6. **부가 기능 미리보기**: 대회·산책로 텍스트 예시이며 실제 일정·운영 정보로 검증되지 않았습니다.

## 인터랙티브 프로토타입

`index.html`은 화면 마크업, `js/courses.js`는 코스 시연 데이터, `js/recommendations.js`는 난이도 필터, `js/safety.js`는 안전 도식·고도 시뮬레이터, `js/app.js`는 화면 상태와 Clerk/Supabase 연동을 담당합니다. 코스 선택→상세→채팅방→안전 안내 흐름을 사용할 수 있습니다. 채팅방 입장만으로 GPS를 수집하지 않습니다. GPS 기록은 체크박스 동의와 시작 버튼을 모두 눌러야 시작하며, 동의를 해제하면 추가 위치 수집을 중단하고 종료 위치 없이 기록을 마칠 수 있습니다. 실제 안전 데이터·지도·크루 실시간 위치·자동 119 신고는 연결되어 있지 않습니다.

### 로컬 실행 및 테스트

저장소 루트에서 정적 미리보기를 실행합니다.

```sh
python3 -m http.server 8000
```

브라우저에서 `http://localhost:8000/`을 엽니다. 단위 테스트는 Node.js 내장 테스트 러너로 실행합니다.

```sh
node --test tests/*.test.cjs
```

로그인·실시간 채팅·영구 GPS 기록은 아래 Clerk/Supabase 설정과 SQL 마이그레이션이 적용되어야 동작합니다. 테스트는 외부 서비스 대신 모의 DB/GPS를 사용하므로 실제 서비스 연결 검증은 별도로 해야 합니다.

### 실시간 소통방 설정

1. Supabase SQL Editor에서 [`supabase/schema.sql`](supabase/schema.sql)을 실행한 후 [`supabase/clerk-migration.sql`](supabase/clerk-migration.sql)을 실행합니다. 기존 프로젝트에서는 두 번째 파일만 실행합니다. 기존 데이터는 유지되지만 기존 Supabase 계정이 Clerk 계정으로 자동 이전되지는 않습니다.
2. Clerk에서 username과 password 가입·로그인을 활성화하고 이메일 필수 설정을 해제합니다. 이메일이나 전화번호가 없으면 비밀번호 자동 복구는 제공되지 않습니다.
3. [Clerk와 Supabase의 third-party auth 연동](https://clerk.com/docs/guides/development/integrations/databases/supabase)을 활성화합니다. 현재 공개 키는 개발 인스턴스용이므로 실제 서비스에는 운영 인스턴스와 도메인이 필요합니다.
4. 프로젝트 URL과 공개 키는 `index.html`에 설정되어 있습니다. 비밀 키는 브라우저 코드에 넣지 마세요. 변경사항을 `main`에 반영하면 GitHub Pages가 배포됩니다.

현재 Clerk 가입 비밀번호는 8자 이상이어야 합니다. Clerk의 비밀번호 정책을 변경하면 가입 화면의 최소 길이 안내와 입력 제한도 함께 변경하세요.

### 산행 안전 정보와 지형 단면

안전 정보 화면에는 고도 알림 시뮬레이터, 비상 안내, 코스별 가상 안전 안내도와 지형 단면이 있습니다. 안내도는 경로·내 위치·크루·휴게시설·사고 구간을 보여주는 시연용 도식이며 실제 GPS나 시설·사고 데이터가 아닙니다. 지형 단면의 휴게시설·사고 구간 표식도 가상 예시이고, 중간 지형선은 외부 GPX·DEM 표고 데이터를 확인할 수 없어 만든 개략 추정입니다. 화면의 안내도와 추정치는 산행이나 안전 판단에 사용하지 마세요. 위성지도와 지도 API는 사용하지 않습니다.

`main` 브랜치에 반영되면 `.github/workflows/deploy-pages.yml`이 GitHub Pages 배포를 수행하고 Pages 활성화를 시도합니다. 저장소 정책이나 권한으로 자동 활성화되지 않으면 GitHub 저장소 설정에서 Pages 배포 원본을 **GitHub Actions**로 지정하세요.

### 마이페이지 및 GPS 트래킹

기존 Clerk·Supabase 설정을 완료한 후 Supabase SQL Editor에서 [`supabase/tracking.sql`](supabase/tracking.sql)을 실행해야 트래킹 기록을 사용할 수 있습니다. 프로필 사진과 닉네임은 Clerk 계정에 저장됩니다.

기존 `tracking.sql`을 실행한 프로젝트는 [`supabase/tracking-altitude.sql`](supabase/tracking-altitude.sql)도 실행해야 최고 고도를 저장할 수 있습니다. 기존 데이터베이스에서 GPS 동의 해제 후 종료 위치 없이 기록을 끝낼 수 있게 하려면 [`supabase/tracking-location-consent.sql`](supabase/tracking-location-consent.sql)을 `tracking.sql` 다음에 적용하세요. 새로 설치할 때는 최신 `tracking.sql`에 이 제약이 포함되어 있습니다.

코스 소통방 입장 동의와 GPS 기록 동의는 별개입니다. 채팅방 입장만으로 위치 권한을 요청하지 않습니다. GPS 기록 체크박스에 동의한 뒤 시작 버튼을 눌러야 시작·종료 좌표와 최고 고도를 수집하며, 종료 버튼으로 기록을 마칩니다. 기록은 본인만 볼 수 있고 크루와 위치를 공유하지 않습니다. 동의를 끄면 추가 위치 측정을 중단하고 종료 좌표를 저장하지 않은 채 세션을 끝낼 수 있습니다. 고도는 브라우저가 위치를 측정하는 동안만 수집하고 주기적으로 저장합니다. 기기·신호에 따라 고도가 부정확하거나 제공되지 않을 수 있고, 화면을 닫거나 백그라운드에 두면 측정이 중단될 수 있습니다.

사용자가 선택한 코스가 실제 위치와 일치하는지 검증하지 않으며 이동 경로는 저장하지 않습니다. 기록은 본인만 볼 수 있고 월별 목록은 시작일을 기준으로 표시됩니다. GPS는 HTTPS와 위치 권한이 필요하며 인터넷 연결 없이는 기록을 저장할 수 없습니다. 진행 중인 기록은 페이지를 닫아도 유지되며 다시 로그인해 직접 종료해야 합니다.
